# Contracts

Contract 1.0.0. VersionSeal owns: Approval Request; Approval Decision; Approval Record; Approval Condition; Approval Scope; Revocation Record; Expiration Record; Verification Result. Records carry schema/tool versions, stable IDs, actor, timestamp, provenance, command, and payload. Consumers accept compatible 1.x, preserve safe unknown payload metadata, and reject incompatible majors. JSON uses `ok/data/error/error_code/tool_version/contract_version`. Offline upstream fixtures identify repository, tag, schema, and checksum.

Hardening contracts add offline RSA-SHA256 and explicit-key HMAC-SHA256 verifier adapters, bounded quorum and role-separation policies, expiry evaluated only against an injected clock, and cross-host merge receipts that expose equal-version divergence while giving explicit revocations precedence.


Queries return at most 1,000 records, inspect at most 1,000 candidate JSON files, and retain at most 8 MiB of record text per page. `truncated` means more candidates remain; use `next_after` with `--after` even for filtered pages with no records. Unsafe filenames are reported but cannot become safe cursors: repair/remove those corrupt entries before continuing if no cursor progress is possible. The runtime still materializes and sorts directory names; the state directory is operator-controlled, not an untrusted unlimited directory service.

Whole-state `validate`, `verify`, and `doctor` fail with `scan_incomplete` when their bounded scan cannot finish and has no other errors. Page through records and validate each ID to inspect larger stores. Verification checks record structure, actor binding, domain rules, and current artifact bytes. It does not authenticate local state or infer whether an approval is revoked/expired; signature, policy, expiry, and replica functions are opt-in library adapters, not CLI authorization gates.

`--dry-run` validates a prospective record without creating state. Missing/empty flag values are usage errors (exit 2). Configuration values follow the published types. Timestamp checks use the Gregorian calendar, and expiry compares UTC instants with zero-padded fractional seconds. Newly invalid calendar dates are rejected rather than treated as approvals with usable timestamps.

Locks use exclusive atomic files. Pre-existing lock directories from older versions remain conflicts; after confirming no writer is active, operators can remove stale lock files/directories. There is no automatic lock stealing. Records and history use atomic no-replace writes; export replaces only with `--force`. New writes publish an exact-byte intent before record/history publication. `recover --id` can complete an interrupted pair without replacement or lock stealing; see [recovery](recovery.md). Claims interrupted before intent publication and legacy locks still require offline operator review. These two files do not provide a simultaneous filesystem snapshot.

`recover` is an additive CLI command. Failed writes retain their durable intent instead of deleting published members. `doctor` and whole-state validation return `pending_writes` metadata and reject incomplete intents. Completed retained intents are accepted only after exact record/history comparison. Byte receipts and file-size limits count UTF-8 bytes.
